## 0. 使用规则

1. **先拆分、后执行**：本文件写完之前禁止开始编码。任何新增任务先补进本文件。
2. **状态图例**：`TODO` 未开始 / `DOING` 进行中 / `BLOCKED` 被阻塞 / `DONE` 完成 / `CUT` 已裁剪。完成必须附证据（文件路径、命令输出、截图、测试名）。
3. **目录所有权**（并行的硬边界，防止互相覆盖）：
   - Lead（主线程）：`docs/`、`server/`、根目录脚本、`engine/models.py`、`engine/__init__.py`、集成与最终验收。
   - Agent-A（Data）：`data/`、`scripts/build_dataset.py`、`scripts/validate_dataset.py`、`scripts/fetch_all_months.ps1`、`data/config/`、`data/geo/`。
   - Agent-B（Engine）：`engine/`（除 `models.py`/`__init__.py`）、`engine/tests/`。
   - Agent-C（Frontend）：`web/` 全部。
   - Agent-D（QA/Docs）：`tests/`、`scripts/check_determinism.py`、`scripts/matrix_check.py`、`docs/模型说明书.md`、`docs/一页纸说明.md`、`docs/演示脚本.md`；不直接改 `engine/`/`web/`，发现问题写报告给 Lead。
4. **契约冻结**：`docs/契约-v1.md` 与 `web/src/fixtures/plan.fixture.json` 是前后端/引擎共同的唯一契约。字段冲突由 Lead 裁决；任何一方需要改契约，先改契约文档 + fixture，再改代码。
5. **凭证红线**：红豆账号、token、`.credentials`、`.oauth_cache.json` 只能留在 `scripts/` 与服务端；不得进入浏览器、导出 HTML、日志或 Git。
6. **真实数据红线**：库存只用红豆 API 快照；不得用静态台账 `free=2517` 冒充当前库存；不得编造暑期库存。缺失月份在页面明确标注。
7. **单一引擎红线**：100/200/500/任意预算只调用 `engine/orchestrator.generate_plan()`，禁止为不同预算写分支方案。
8. **并行同步点**：T+4 契约/数据可用；T+8 引擎出 fixture；T+12 前后端联调；T+18 功能冻结；T+22 文档/测试冻结；T+24 彩排。

## 8. 验收矩阵（必须逐项打勾）

- [ ] 预算阶梯曝光/Reach 不下降；边际效率下降或有解释。
