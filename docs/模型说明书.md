# 模型说明书 — 乐园行业户外媒体组合优化模型

> 项目：INTERCITY HACK 湖州场 · AI+办公赛道 · 上海新云传媒
> 模型版本：1.0 ｜ 文档版本：1.0 ｜ 日期：2026-11-21
> 适用范围：乐园（主题公园）行业；上海乐高乐园为主，迪士尼/海昌可切换
> 代码入口：`engine/orchestrator.py::generate_plan()` ｜ 契约：`docs/契约-v1.md`

---

## 0. 一句话

这是一个**确定性组合优化模型**：输入「场馆 + 预算 + 媒体 + 2027 档期 + 客户类型」，输出一份可解释、可复算、可交互的户外投放方案（选点、报价、排期、效果、校验）。
**AI 负责理解与解释，算术全部由确定性模型完成。**

---

## 1. 建模问题：三层耦合

| 层 | 数学本质 | 本项目对应 |
|---|---|---|
| L1 选哪些线路/点位 | 有界背包 / 多重背包（预算=容量，库存=上界） | 公交车辆数、地铁出入口 0/1 |
| L2 覆盖是否达标 | 最大覆盖选址 MCLP（Church 1974）的加权版 | 场馆圈层、POI 浓度、区县覆盖 |
| L3 能否落地 | 资源受限排程 RCPSP + 约束满足 | 夜间施工批次、雨备、误一补二、监测 SLA |

三层**耦合**：选点决定覆盖，覆盖决定效果，效果/点位决定施工量与排期。因此本项目用**一个 CP-SAT 模型同时解 L1+L2+L3 的可行域**，而不是串联三个独立模型。

**为什么不让 LLM 算**：LLM 无法保证三层约束同时满足，也无法保证换预算后结果可复现。LLM 只做 brief 理解、策略检索、解释生成。

## 2. 输入

### 2.1 结构化输入（API/工作台）

```json
{
  "industry": "乐园",
  "venue": "lego_shanghai",
  "budget_wan": 500,
  "media": ["bus", "metro"],
  "start_date": "2027-07-01",
  "weeks": 8,
  "customer_type": "direct",
  "locks": { "include": [], "exclude": [] },
  "brief_text": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `industry` | string | 固定 `乐园`（当前版本） |
| `venue` | string | `lego_shanghai` / `disney_shanghai` / `haichang_shanghai` |
| `budget_wan` | number | 100–500 万，连续；默认 500 |
| `media` | string[] | `bus` / `metro`，至少 1 项 |
| `start_date` | string | 2027 年内，且落在已抓取快照月份 |
| `weeks` | int | 2/4/6/8/12；默认 8 |
| `customer_type` | string | `direct`（直客，无 4A 费）/ `4a`（15% 服务费） |
| `locks.include` | string[] | 锁定资源 ID；无库存返回 `LOCK_CONFLICT` + 建议 |
| `locks.exclude` | string[] | 排除资源 ID |
| `brief_text` | string? | 自然语言 brief；仅用于策略解析，不进入算术链路 |

**派生字段**：`end_date = start_date + weeks*7 - 1`；`months` = 覆盖的自然月数（向上取整，最少 1）；`cache_key` = 规范化请求 JSON。

### 2.2 自然语言输入（可选）

示例：

离线解析器抽取 venue/budget/media/日期/customer_type，生成受约束的结构化补丁；无法识别的字段用默认值并提示。**LLM 可选增强，但不得输出数字。**

## 4. 中间处理流程（11 步）

```
[1] Brief 解析（可选 NL） → 结构化 PlanRequest
      │
[2] 载入场馆 skill / venue profile → 人群、交通、圈层、配比、POI 权重、reach_k、合规
      │
[3] 载入红豆月度快照 → 去重 → 过滤 free<=0 / specialSituation / 未知等级 → 跨月 min_free
      │
[4] 候选富化 → 价格、曝光代理、场馆亲和、POI 浓度、区县权重、换乘、边际衰减、评分分解
      │
[5] 预算切盘 → 公交/地铁按 venue 配比切预算；单媒体自动 100%；盘内按有效价值/元排序
      │
[6] CP-SAT 求解 → 公交整数 + 地铁 0/1；预算/库存/配比/等级/数量/产能/覆盖/锁定/排除
      │
[7] 折扣不动点 → 88% 起算，按刊例总额落档，最多 5 轮；循环取最保守可行解
      │
[8] 效果估算 → 有效曝光 → GRP → Reach/Frequency/CPM；公交+地铁单一饱和曲线（不相加）
      │
[9] 报价 → 刊例×折扣 + 制作 + 4A + 赠媒；逐行分摊加总 == 总价
      │
[10] 排期 → 夜间批次/雨备/上刊/监测/下刊/误一补二/替换池；批次 units == 付费 units
      │
[11] 独立校验 + 解释 → blocker/warning；H1–H7 回链；反事实；输出 PlanResponse
```

### 4.1 候选富化的评分

对每个候选点位 i：

```
exposure_i     = 日均客流(等级) × 可视率 × 天数 × units
audience_fit_i = w_venue×场馆距离衰减 + w_poi×POI 命中 + w_district×区县权重
                 + w_corridor×换乘/枢纽 + w_media×媒介角色
slot_value(i,k)= exposure_i × audience_fit_i × decay^(k-1)
score_i        = 归一化(slot_value / 单位成本)
```

- 公交：日均客流 S 58,000 / A++ 48,000 / A+ 38,000（AA 默认不付费）；可视率 0.60。
- 地铁：A++ 90,000 / A+ 55,000 每口；可视率 0.50。
- 乐高无地铁直达：场馆亲和用 **6/20/50km 圈层 + 家庭客源枢纽 + POI 浓度**，不硬套 6km 过滤。
- 公交无真实几何时用品类/运营公司区域代理，标 `schematic`，不下调成“精确距离”。
- 评分分解写入 `score_breakdown`，供地图抽屉逐项质询。

### 4.2 预算切盘与边际递减

- 双媒体：按 venue `media_mix_bounds`（乐高公交偏重、迪士尼地铁偏重、海昌混合）切预算，盘内按 `slot_value / 单位成本` 排序。
- 单媒体：自动 100%，不强行套双媒体配比。
- 同一线路/站点重复投放：`decay^(k-1)`，默认 `decay=0.72`（可在配置调整）。
- 预算增加时可行域扩大，最优曝光不下降；组合变化以“扩充”为主，不推翻已选。

## 5. 数学模型（CP-SAT）

### 5.1 决策变量

- 公交：`u_bus[i,k] ∈ {0,1}`，`k = 1..min(free_i, 4)`；前缀约束 `u[i,k+1] <= u[i,k]`；`x_i = Σ_k u[i,k]`。
- 地铁：`u_metro[j,k] ∈ {0,1}`，`k = 1..min(free_j, 2)`；`y_j = Σ_k u[j,k]`。
- 选择：`b_bus[i]`, `b_metro[j] ∈ {0,1}`；`b <= x <= free*b`。
- 区县覆盖：`z[d] ∈ {0,1}`，表示区县 d 至少一个付费点位。
- 目标全部整数缩放，避免浮点不确定性。

### 5.2 约束

| # | 约束 | 表达式/说明 |
|---|---|---|
| 1 | 预算 | `Σ 单价×units×months×discount + 制作费 + 4A 费 ≤ 预算` |
| 2 | 库存 | 公交 `x_i ≤ min_free_i`；地铁 `y_j ≤ min_free_j` |
| 3 | 单项上限 | 公交 ≤4 辆/线/媒体；地铁 ≤2 口/站 |
| 4 | 数量 | 公交启用线路 4–35；地铁站 2–24；单媒体/小供给自动放宽 |
| 5 | 媒介配比 | 双媒体按 venue 上下限；用刊例口径计算占比 |
| 6 | 等级配比 | 公交 S+A++ 占 units 35–80%；地铁 A++ 占 20–90%；样本过小时自动关闭 |
| 7 | 公司分散 | 单运营公司公交 ≤15 辆；输出集中度 |
| 8 | 施工产能 | `bus_units ≤ nights×20`；`metro_units ≤ nights×10` |
| 9 | 锁定 | 锁定项 `b=1, x≥lock_units`；无库存 → `LOCK_CONFLICT` + 建议 |
| 10 | 排除 | 排除项移出候选，不进入模型 |
| 11 | 区域覆盖 | `z[d] <= Σ_{i覆盖d} b_i`，仅作次级目标 |
| 12 | 档期 | 只使用与请求档期重叠的月度快照；跨月取 min |

**不可行处理**：先诊断，再按顺序松弛（低等级占比下限 → 媒介最小配比 → 线路/站点数量下限 → 建议预算/解锁），每条松弛写 notice。**库存与预算约束绝不放松；技术异常才走降级链。**

### 5.3 目标

```
maximize  Σ slot_value(i,k) × u[i,k] × 1,000,000
        + Σ demand[d] × z[d] × 1,000
        + stable_tie_break(i)
```

- 主项：有效曝光代理（等级/媒体/人群适配/衰减）。
- 次项：区县覆盖 tie-break，不得反转主项。
- 第三项：稳定 ID 排序，避免同分随机。
- 不含“成本最小化”单独目标：预算约束已限制总成本，主目标最大化曝光；折扣由外层不动点处理。

### 5.4 求解设置

| 项 | 值 |
|---|---|
| 求解器 | OR-Tools CP-SAT（主）/ SciPy HiGHS（备）/ 确定性贪心（最后） |
| 线程 | `num_search_workers=1` |
| 种子 | `random_seed=42` |
| 时间上限 | 每轮 1.5 秒 |
| Hint | 先用贪心解作 solution hint |
| 状态 | `OPTIMAL` / `FEASIBLE` / `INFEASIBLE` |
| 降级 | 仅技术异常触发；`fallback_chain` 写入 meta，页面显示黄色警告 |
| 复现 | 同输入 5 次，除 `generated_at/request_id/solve_ms/total_ms/cache_hit` 外完全一致 |

### 5.5 折扣不动点

```
d0 = 0.88
repeat up to 5:
    solve with discount d
    gross = Σ 单价×units×months
    d' = tier(gross)          # 88/83/78/73/68%
    if d' == d: converged
    d = d'
if cycle: choose most conservative feasible solution; discount_converged=false
```

档位（按全单刊例总额）：

| 档位 | 最低刊例 | 折扣 |
|---|---:|---:|
| 1 | 0 | 88% |
| 2 | 100 万 | 83% |
| 3 | 200 万 | 78% |
| 4 | 300 万 | 73% |
| 5 | 400 万 | 68% |

> 门槛为规划假设；折扣率 88/83/78/73/68% 来自赛前培训/PRD 口径，待赞助方确认。配置集中在 `data/config/rate_card_2027.json`。

### 5.6 效果模型

```
有效曝光 = Σ units × 日均客流 × 可视率 × 天数 × audience_fit × decay^(k-1)
GRP      = 有效曝光 / 目标人群 × 100
Reach    = reach_cap × (1 − exp(−GRP / k_eff))
Frequency= (GRP/100) / Reach
CPM      = 折后媒体费(元) / 有效曝光 × 1000
```

参数：

| 参数 | 值 | 来源/说明 |
|---|---:|---|
| `reach_cap` | 0.82 | 物理媒体到不了 100%；行业保守上限 |
| `k`（乐高/迪士尼/海昌） | 250 / 240 / 245 | venue profile；可调 |
| `k_eff` 双媒体 | `k × 1.10` | 承认渠道重叠 |
| 公交日均客流 | S 58,000 / A++ 48,000 / A+ 38,000 | 等级经验值；待可视化平台数据校准 |
| 地铁日均 | A++ 90,000 / A+ 55,000 每口 | 模型经验值 |
| 可视率 | 公交 0.60 / 地铁 0.50 | 行业经验值 |
| 目标人群 | 乐高 250 万（策划假设） | 上海及周边亲子家庭；非调研数字 |

**不允许把公交 Reach 与地铁 Reach 相加**；合并使用单一饱和曲线。`by_media` 只展示曝光贡献，不展示可加总的到达率。

### 5.6.1 九档弹性

- 预算 100/150/…/500；同一优化器的**确定性预算扩展估值**（greedy 路径，保证曝光不随预算下降），主方案仍用 CP-SAT。
- `knee_budget_wan` = Reach 达到最高值 98% 的预算；之后加钱主要买频次/枢纽覆盖。
- 首次 `/api/elasticity` 约 5.7s（9 档），之后缓存约 24ms；单主方案约 1.7s。
- 局限：弹性点为快速估值，与 CP-SAT 主方案可能存在差异（页面/文档已标注）；主方案 KPI 以 `effects` 为准。

### 5.7 报价

```
rate_card_total = Σ 单价 × units × months
media_net       = rate_card_total × discount
production      = 公交 0.75 万/辆 + 地铁 0.03 万/口
agency_fee      = media_net × 15%（仅 4A）
total_paid      = media_net + production + agency_fee
gift            = media_net × 5%（等值赠媒，不计付费 KPI）
total_paid <= budget
Σ 行分摊 == total_paid（误差 ≤1 元）
```

### 5.8 排期

- 阶段：设计 → 定稿 → 内容审批 → 制作 → 夜间安装 → 上刊 → 监测 → 下刊 → 结案。
- 夜间窗口 23:00–05:00；公交 20 辆/晚、地铁 10 口/晚；10 个可用夜；2 个雨备夜。
- 批次按优先级排序，逐批填满；安装完成日必须早于 go-live。
- 监测 SLA：4A brief 2 个工作日；上刊照片当日/次日；上刊监测 5 个工作日；下刊 5 个工作日；月度报告。
- 误一补二；库存被占按“同站其他口 → 相邻枢纽 → 同区县”替换并说明理由。
- validator 校验：批次 units 总和 == 付费 units；安装日期在 go-live 前；雨备存在。

## 6. 独立校验（validator）

validator **不导入 solver**，只检查请求、原始快照与响应：

| 编号 | 检查 | 级别 |
|---|---|---|
| V1 | 预算不超 | blocker |
| V2 | 库存不超（min_free） | blocker |
| V3 | 无 specialSituation 封闭口/未知等级 | blocker |
| V4 | 媒介配比在容差内 | warning |
| V5 | 线路/站点数量 | warning |
| V6 | 施工产能/批次覆盖 | blocker |
| V7 | 逐行分摊加总 == 总价 | blocker |
| V8 | 折扣档位合法 | blocker |
| V9 | 效果无 NaN、Reach ≤ cap、公式一致 | warning |
| V10 | 假设书 H1–H7 非空且被引用 | blocker |
| V11 | 每个付费点位有 reasons/evidence | warning |

## 7. 可解释性与 AI 工作流

### 7.1 解释输出

- `why_selected`：每个点位 1–3 条理由 + 证据（库存/POI/换乘）。
- `why_not`：为什么没选竞品站点、远郊低价线路、全铺高价地铁。
- `trim_priority`：砍预算先砍谁（按边际曝光/万元从低到高）。
- `counterfactuals`：100 万、换场馆、库存冲突三个现场高频问题。
- `hypothesis_links`：每个模块回链 H1–H7。

### 7.2 AI 工作流（真实执行）

| 阶段 | 实现 | 是否产出数字 |
|---|---|---|
| Brief 解析 | 离线规则/关键词；可选 LLM | 否 |
| 策略检索 | venue profile + 知识片段 TF-IDF/关键词 | 否 |
| 候选富化 | 确定性公式 | 是 |
| CP-SAT 求解 | 确定性求解器 | 是 |
| 独立校验 | validator | 否 |
| 解释生成 | 模板 narrator，只引用 JSON 数字 | 否 |

**护栏**：LLM 不产出预算/库存/报价/曝光数字；无 API Key 自动离线；`workflow.llm_used=false` 时页面显示“离线规则模式”，不假装 AI。

## 9. 确定性、缓存与性能

- 求解器全整数、单线程、固定 seed；输出按媒体/价值/ID 稳定排序。
- 缓存键：规范化请求 + `data_version` + `config_version`；LRU；响应头 `X-Cache`。
- 启动预热默认 100/200/500；滑杆 250ms 防抖；旧结果保留，不白屏。
- 实测：单主方案约 1.7s（CP-SAT，600ms 上限 + 折扣不动点）；九档弹性首次约 5.7s、缓存约 24ms；启动预热默认场景。
- 降级链：CP-SAT → HiGHS → 贪心；每次降级写 `meta.fallback_chain`，页面显示警告；validator 仍必须通过。

## 10. 局限与待确认

1. 曝光/Reach/Frequency/CPM 为估算，不是实测触达；目标人群为策划假设。
2. 折扣门槛 88/83/78/73/68% 的精确分层待赞助方确认。
3. 地铁 `lineLevel` 2=A++ / 3=A+ 为假设；红豆未给精确语义。
4. 公交几何缺失时为区县示意；POI/站点坐标为公开近似，不用于测量级结论。
5. POI 共 103 个（目标 112+，已知差 9 个）；6 类以上，后续可扩。
6. 九档弹性为 greedy 预算扩展估值，主方案为 CP-SAT；两者共享库存/配比/预算规则，数值可能不同。
7. 库存为查询时点快照，档期占用会变化；演示前需核对并显示时间戳。
8. 未接入历史案例库/可视化平台“AI 线路”实时数据；后续可替换自建廊道/距离。
7. 不做转化归因；不承诺入园人数、销量、收益。
8. 施工产能（20 辆/晚、10 口/晚、10 夜、2 雨备）为规划假设，源文档未给精确数值。
