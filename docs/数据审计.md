## 2. 关键发现

1. **库存随月份变化**：279 条公交业务键、34 个地铁口在 2027-06..10 间 `freeCount` 发生变化。示例：
   - `100|大三侧`：6/7/8 月 2 → 9/10 月 3
   - `1002|车身三侧`：6/7 月 2 → 8/9/10 月 4
   - `1004|车身三侧`：6 月 1 → 7–10 月 0
   → 提案必须按目标档期查库存；跨月投放取**最小可售**，不能把 6 月和 8 月相加。
2. **静态台账不可用**：资料包 `01-公交媒体台账.xlsx` 是 2026-11-13 单日快照，free=2,517；2027-01 API 快照 free=1,237，相差近一倍；2027-07/08 为 1,470/1,545。禁止用静态台账当库存。
3. **地铁封闭口**：每月 9 条 `specialSituation`（封闭/改造），必须剔除，不得进入方案。
4. **地铁 274 站 / 861 口**：每口 `totalCount=1`、`freeCount` 0/1；适合 0/1 变量，不适合“车辆数”变量。
5. **等级分布**（bus）：S 48 行 / A++ 200 / A+ 181 / AA 2；地铁 `lineLevel` 仅 2/3（按合约假设映射 A++/A+，页面标注）。
6. **接口坑**：`total` 不可信（bus 声称 552，实返 431）；每页实返 < pageSize；只以“0 条/连续 3 页无新行”停止；401 自动重登；token 短时有效。

## 3. 数据流与版本

```
红豆 API (bus/metro page)
  → data/snapshots/{bus|metro}_YYYY-MM-01_YYYY-MM-31.csv   (raw，只读)
  → build_dataset.py 去重/过滤/等级/min_free
  → data/processed/manifest.json + inventory.json + candidates_enriched.json
  → engine/data_loader.load_inventory(request)
  → CP-SAT 候选集
```

- `data_version`：manifest + config + venue profile 的 SHA256 前 12 位；缓存与页面均引用。
- `inventory_ts` / `inventory_periods`：页面顶部与校验页展示。
- 凭证：`scripts/.credentials`、`.oauth_cache.json` 已 gitignore；不进入前端/导出。

## 6. 审计结论

- 主档期使用 **2027-07/08 快照**；跨月取最小可售；页面显示时间戳/档期。
- 所有库存数字来自红豆 API，不来自静态台账。
- 地铁封闭口/未知等级剔除；缺失地理数据明确标 `approx/low/schematic`。
- 任何无法确认的数字标“未确认/假设”，不伪造。
- POI 103 个略低于 PRD 的 112 个目标，已在测试报告/页面标注；后续可用公开数据扩充。
