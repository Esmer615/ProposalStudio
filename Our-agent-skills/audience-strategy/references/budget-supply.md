# 预算与供给：怎么读弹性（audience-strategy 参考）

## 1. 不要背死数字

旧版 skill 里的“科技馆 22 个点位、约 40–50 万买满”来自上一个 JS 原型，
当前库存快照、候选池、POI 库都变了。**不要原样引用。**

正确做法：用本次 `elasticity` 与 `plan.summary` 说话。

## 2. 弹性返回什么

```jsonc
{
  "unit": "万元",
  "points": [
    {
      "budget_wan": 100,
      "impressions": 12919173,
      "reach": 0.6948,
      "frequency": 7.44,
      "cpm_yuan": 65.39,
      "marginal_impressions_per_wan": 0,
      "delta_reach": 0.0,
      "is_current": false
    }
  ],
  "knee_budget_wan": 200,
  "note": "同一优化器的确定性预算扩展估值（greedy）；主方案以 CP-SAT 结果为准。"
}
```

- `knee_budget_wan`：Reach 达到最高值 98% 的预算。超过它，加钱主要买频次/覆盖。
- `marginal_impressions_per_wan`：边际每万元曝光；整体趋势应递减。
- 弹性曲线是 **greedy 扩展估值**，不是主方案的 CP-SAT；话术要标清楚。

## 3. 分档逻辑

钱少时先买高浓度点位；钱多时必须向更广的点位溢出。不是“我们想投这儿”，
是“库存买满了，只能往下溢出”。

在提案里怎么讲：

> 「预算到 X 万以后，符合条件的高浓度点位基本买满；再往上加，
> 引擎会把钱放到更广的点位。这不是策略选择，是库存约束。
> 所以我们把它讲成分档：第一档买浓度，第二档买规模。」

## 4. 预算使用率

```
utilization = quote.total_paid_wan / inputs.budget_wan
```

- ≥85%：基本花满。
- 70–85%：部分未花完，必须说明。
- <70%：供给或约束卡住，不能直接推荐。

**不要再说“预算一定花满”。** 当前引擎会保留制作费、赠媒、代理费的差异，
库存也可能买空。

## 5. 什么时候加场景

- 客户问“再加钱值不值” → 加上探 + 拐点。
- 客户问“砍到 X 万怎么做” → 加下探。
- 客户问“为什么不再多投一点” → 用拐点和频次回答。
- 客户没有预算概念 → 基准 + 上下探，给区间。
