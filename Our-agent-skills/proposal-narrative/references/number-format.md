# 数字表述规范（proposal-narrative 参考）

## 1. 单位与精度

| 场景 | 格式 | 示例 | 注意 |
|---|---|---|---|
| 预算 | 万元，整数或一位小数 | “200 万” | 不写“2,000,000 元” |
| 报价/落地 | 万元，一位小数 | “188.4 万” | 与预算同单位 |
| 剩余 | 万元，一位小数 | “剩余 11.6 万” | 必须主动说 |
| 总曝光 | 万人次，千分位 | “2,655 万人次” | 标“模型估算” |
| 目标 Reach | 百分比一位小数 + 人数 | “80.3%，约 201 万人” | 人数 = reach × 目标人群 |
| 频次 | 一位小数 + 次 | “13.2 次” | 模型估算 |
| CPM | 元，两位小数 | “66.98 元” | 混合口径 |
| 效率 | 人次/万元 | “每万元 14,094 人次目标 Reach” | 写清是 Reach 还是总曝光 |
| 折扣 | 百分比整数 | “78%” | 全单落档 |
| 占比 | 百分比整数或一位小数 | “94.2%” | 预算使用率保留一位 |
| POI | 个 | “命中 71 个” | 公开近似 |
| 车/口/线/站 | 整数 + 单位 | “公交 14 辆 / 13 条线；地铁 2 口 / 2 站” | 不要混用“点位” |

## 2. 派生数字必须带公式

- `reach_people = effects.reach × effects.target_population`
- `utilization = quote.total_paid_wan / inputs.budget_wan`
- `reach_people_per_wan = reach_people / quote.total_paid_wan`
- `premium_share = (S + A++ + A+) units / total units`

话术里可以说“约”，但必须给出原始字段或公式，不能只给一个“约 300 万”。

## 3. 禁止

- 把总曝光说成目标人群曝光。
- 把 `reach`（比例）说成人数。
- 把公交和地铁的 reach 相加。
- 用“约”掩盖没有依据的数字。
- 引用分析结果里不存在的数字（LLM 润色时尤其注意）。
- 把 2027 写成 2026/2028；日期必须来自 request。

## 4. 一致性检查

- 预算 - 实际落地 = 剩余（允许 0.1 万四舍五入误差）。
- 公交 + 地铁花费占比 ≈ 100%。
- Reach 百分比 ≤ reach_cap（通常 82%）。
- 评分只在同一 objective 下有相对意义，不跨 objective 比较。
