# 说人话：让每一句话都能被追问而不崩

## 0. 为什么需要这一层

同一份计算结果，说法不同，可信度天差地别：

> ❌「本方案预计触达 287 万人次目标人群，ROI 显著提升」
> ✅「本方案在模型估算口径下，目标人群 Reach 80.3%；实际到园无法归因，所以我们不承诺人数」

前者像 PPT，后者像人话。评委和客户都会更信后者。

**这一层的唯一目标：每一句话都能被追问而不崩。**

---

## 1. 四条铁律

### 铁律 1：数字必须带口径

| 数据来源 | 必须怎么说 |
|---|---|
| 红豆快照 | 「红豆 2027 月度库存快照，数据版本 X；上刊前需重核占用」 |
| 模型曝光 | 「模型估算，不是实测」 |
| POI/人群 | 「公开近似 POI 库，不是测量级数据」 |
| 平台人流 | 「当前未接入平台实测区域人流」 |
| 折扣 | 「按全单刊例总额落档，档位口径待赞助方确认」 |

**没有口径的数字 = 编的。**

### 铁律 2：曝光 ≠ 到园

| ❌ | ✅ |
|---|---|
| 预计带来 X 人到园 | 预计触达 X 万人次目标人群，实际到园无法归因 |
| ROI 达到 X | 每万元买到 X 人次目标曝光 |
| 转化率 X% | 这个数字我们没有数据支撑，不给 |

户外广告没有点击、没有归因链路。**说能算到园转化的，都是在赌。**

### 铁律 3：钱没花完必须说

看 `utilization = quote.total_paid_wan / inputs.budget_wan`：

- ≥85%：可以说“基本花满”。
- 70–85%：主动说“部分未花完”，并给选择：放宽约束 / 降预算 / 换档期。
- <70%：不能直接推荐。

**旧版 skill 说“预算一定花满”，在当前 Python 引擎里是错的。**
当前方案会包含制作费、赠媒、代理费；库存也可能买空。实测 200 万方案落地 188.4 万（94.2%）。

### 铁律 4：不投校内

统一措辞：**“学校周边 300–500 米的地铁/公交点位”**。
不能说“投在学校里”“校园内推广”“和学校合作投放”。

## 2. 按场景的话术模板

### 2.1 开场（30 秒内建立可信度）

> 「这单我们给两个场景：一个看覆盖，一个看效率。我先说结论，再说为什么——
> **所有数字都标了口径，你们随时可以质疑。**」

主动暴露“我准备被质疑”，比全程自信更有说服力。

### 2.2 报方案（结构化三句）

```
第一句：方案是什么（预算/媒介/关键数字）
第二句：为什么这么买（库存约束 / 人群判断 / 交通结构）
第三句：代价是什么（预算没花完 / 覆盖浓度下降 / 频次上升）
```

示例：

> 「**基准方案**：200 万预算，实际落地 188.4 万（使用率 94.2%），
> 公交 14 辆 / 地铁 2 站，总曝光 2,655 万人次，目标人群 Reach 80.3%（模型估算）。
> 这么买是因为乐高无地铁直达，公交做社区广度，地铁只买家庭出发枢纽。
> 代价是地铁曝光占比只有 11.6%，且剩余 11.6 万未花完。」

**第三句最重要**：主动说代价，比藏着掖着强十倍。

### 2.3 被问“数据哪来的”

> 「分四层：
> 库存和刊例——红豆 2027 月度快照，数据版本 X；
> 人群/POI——公开近似 POI 库，不是测量级；
> 曝光/Reach——引擎饱和曲线模型估算，不是实测；
> 折扣——按全单刊例落档，档位口径待赞助方确认。
> 哪一层你想细问，我都能指到原始字段。」

### 2.4 客户砍预算

> 「砍到 100 万不用重做方案——改预算，引擎重算。
> 但你要知道代价：预算使用率、点位数、Reach 分别怎么变。
> **不是“每一分钱都更值”这么简单，要看库存能不能吸收。**」

### 2.5 被问“为什么不用 AI 直接生成方案”

> 「报价和库存算错了是商业事故。评委现场改预算，我们要快速出结果，而且**每次必须一样**——
> 大模型做不到确定性复算。AI 我们用在两个地方：理解客户需求、解释选点理由。
> 算钱的部分锁在规则里。」

### 2.6 被问“这个方案能落地吗”

> 「单文件 HTML，销售在自己电脑上双击就开；接红豆导出件一条命令。
> 不需要服务器、不需要 API Key；所有数字可追溯到引擎字段。」

## 3. 高频问题的标准答案

| 问题 | 一句话答案 |
|---|---|
| 目标人群怎么定义？ | 当前只能到 <20 岁这一档口径；目标人群基数是场馆档案的策划假设，不是实测去重人群 |
| 为什么投学校周边？ | 不投校内。投学校周边 300–500 米的地铁/公交点位，合规且同人群 |
| 曝光会不会重复？ | 会。Reach/Frequency 用饱和曲线估算，公交和地铁合并成一条曲线，不直接相加 |
| 预算越高越划算吗？ | 不一定。看 `knee_budget_wan`；超过拐点后加钱主要买频次，不是新增到达 |
| 换迪士尼还成立吗？ | 成立，但策略会变。迪士尼 11 号线直达可做廊道拦截；乐高无地铁，只能打家门口曝光 |
| 为什么有的方案钱没花完？ | 库存/约束买满了，或制作费/赠媒占了一部分；使用率 <85% 必须主动说 |

## 4. 危险措辞对照表

| 危险说法 | 为什么危险 | 改成 |
|---|---|---|
| “投在学校里” | 合规红线 | “学校周边 300–500 米” |
| “预计带来 X 人到园” | 无法归因 | “触达 X 万人次目标人群，到园不可归因” |
| “ROI 达到 X” | 户外无转化数据 | “每万元买到 X 人次目标曝光” |
| “触达 287 万人”（无口径） | 会被追问口径 | “目标人群 Reach X%（模型估算）” |
| “预算一定花满” | 旧引擎口径，当前会翻车 | “预算使用率 X%，剩余 Y 万未花完” |
| “这是最优方案” | 抹杀了权衡 | “这两个方案分别适合…” |
| “AI 生成的方案” | 暗示不可控 | “规则引擎计算 + AI 解释” |
| “全上海都能看到” | 夸大 | “覆盖 X 个区县 / Y 个 POI 圈层，总曝光 Z 万人次（模型估算）” |
| “精准/广度/廊道策略” | 当前引擎没有这些参数 | “预算下探/上探/媒体组合参考” |

## 5. 数字表述规范

| 场景 | 格式 | 示例 |
|---|---|---|
| 预算 | 万元 | “200 万” |
| 报价 | 万元，一位小数 | “188.4 万” |
| 曝光 | 万人次，千分位 | “2,655 万人次” |
| 目标 Reach | 百分比，一位小数 + 人数 | “80.3%，约 201 万人” |
| 频次 | 一位小数 | “13.2 次” |
| CPM | 元，两位小数 | “66.98 元” |
| 效率 | 人次/万元 | “每万元 14,094 人次目标 Reach” |
| 折扣 | 百分比整数 | “78%” |
| 占比 | 百分比整数或一位小数 | “94.2%” |

**禁止**：模糊数“约 300 万”却不给依据；必须给准确值或明确区间。

---

## 6. 三个必须主动说的局限

在方案讲完、还没被问之前，主动说：

1. **曝光/Reach/频次/CPM 是模型估算，不是实测**；当前未接平台实测人流。
2. **POI 坐标/类型是公开信息近似**，不用于测量级结论。
3. **折扣是区间化口径**，真实折扣依合同类型浮动；4A 另加 15% 服务费。

> 「这三条是我们自己写的局限页。**先自己说出来，比被你们问出来强。**」

## 7. 收尾话术

> 「一句话：这个工具不是让 AI 替销售写 PPT，是**把销售三天的活压成三分钟，
> 而且每一分钱都对得回红豆的库存和引擎字段**。
> 客户砍预算，销售不用重做方案，改一个输入就能说清少买的是什么。」
